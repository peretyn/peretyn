---
title: Self-hosting
description: Run the Peretyn stack on your own server with Docker Compose.
---

The Compose stack runs Peretyn on one host: the runtime, the control plane, the dashboard, PostgreSQL, and Caddy in front of them. Caddy gets a TLS certificate for your domain, and it is the only service that publishes ports. To see what the stack doesn't do yet, such as running on more than one host, read [Limits and guarantees](/limits).

You need a Linux host with Docker, a domain whose DNS record points at the host, and ports 80 and 443 open. To try Peretyn without a domain, see [Try it on this machine](#try-it-on-this-machine).

The domain must be a public name. The installer refuses an IP address, because no client can verify a TLS certificate for one. It warns about names under suffixes reserved for private networks, such as `.test`, `.local`, `.internal` and `.lan`, because they can't get a public certificate.

## Install

Run the installer as root:

```sh
curl -fsSL https://peretyn.dev/install | sh
```

It asks for your domain and the first admin's email, then:

- pins the latest `@peretyn/runtime` release and downloads `compose.yaml` and the `Caddyfile` from that release into `/opt/peretyn`,
- generates every secret into `.env`, readable only by its owner,
- starts the stack,
- creates the admin account and prints its password once.

To install somewhere else, or as a user in the `docker` group, set `PERETYN_DIR` to a directory you own.

### Unattended install

Every question has a variable. Set them and the installer asks nothing:

```sh
curl -fsSL https://peretyn.dev/install |
  PERETYN_DOMAIN=peretyn.example.com PERETYN_ADMIN_EMAIL=you@example.com PERETYN_ADMIN_NAME='Your Name' PERETYN_RESEND_API_KEY= sh
```

| Variable                 | Description                                                            |
| ------------------------ | ---------------------------------------------------------------------- |
| `PERETYN_DOMAIN`         | The domain that Caddy serves, or `localhost`. Required.                |
| `PERETYN_ADMIN_EMAIL`    | The first admin's email. Required.                                     |
| `PERETYN_ADMIN_NAME`     | The first admin's name. Set it empty to use the email's local part.    |
| `PERETYN_RESEND_API_KEY` | A [Resend](https://resend.com) API key. Set it empty to send no email. |
| `PERETYN_TAG`            | The version to install. Defaults to the latest release.                |
| `PERETYN_DIR`            | The install directory. Defaults to `/opt/peretyn`.                     |

### Try it on this machine

To evaluate Peretyn on a laptop or a box with no DNS, install it on `localhost`:

```sh
curl -fsSL https://peretyn.dev/install |
  PERETYN_DOMAIN=localhost PERETYN_ADMIN_EMAIL=you@example.com PERETYN_ADMIN_NAME= PERETYN_RESEND_API_KEY= sh
```

With `localhost`, Caddy serves plain HTTP at `http://localhost`, so there is no certificate to trust. Open the dashboard at `http://localhost` from the same machine, and use it as the URL in the [Quickstart](/quickstart):

```sh
export PERETYN_URL=http://localhost
```

Keys and passwords travel unencrypted, so use this install only for evaluation, and only from the machine it runs on. To move to a real domain, uninstall it and install again with your domain.

### Verify before running

Each `@peretyn/runtime` release carries `install.sh` and its `SHA256SUMS`. Download both from the release, check the script, read it, then run it:

```sh
gh release download '@peretyn/runtime@<version>' -R peretyn/peretyn -p install.sh -p SHA256SUMS
sha256sum -c SHA256SUMS
sh install.sh
```

### Verify the images

Release images carry signed build provenance. Check that an image was built by this repository's release workflow:

```sh
gh attestation verify oci://ghcr.io/peretyn/peretyn/runtime:<version> -R peretyn/peretyn
```

The same works for `control` and `dashboard`.

### Install by hand

#### 1. Download the files

```sh
mkdir -p /opt/peretyn && cd /opt/peretyn
base=https://raw.githubusercontent.com/peretyn/peretyn/main/deploy
curl -fsSLO "$base/compose.yaml"
curl -fsSLO "$base/Caddyfile"
curl -fsSL "$base/.env.example" -o .env
```

#### 2. Fill in `.env`

Set every variable that [Configuration](#configuration) marks as required. Generate each secret with `openssl rand -hex 32`.

#### 3. Start the stack

```sh
docker compose up -d
```

#### 4. Enroll the first admin

Sign-up is closed by default, so create the first account from the command line:

```sh
docker compose exec control node services/control/dist/scripts/enroll.js you@example.com 'password' 'Your Name' --admin
```

## Enroll more people

Create other accounts the same way, without `--admin`, from the install directory:

```sh
docker compose exec control node services/control/dist/scripts/enroll.js teammate@example.com 'password' 'Their Name'
```

Admins manage users through the better-auth admin endpoints under `/api/auth/admin/*`.

## Configuration

| Variable                  | Required | Description                                                                 |
| ------------------------- | -------- | --------------------------------------------------------------------------- |
| `PERETYN_TAG`             | Yes      | The server version to run, such as the latest `@peretyn/runtime` release.   |
| `PERETYN_DASHBOARD_URL`   | Yes      | The URL that Caddy serves, such as `https://peretyn.example.com`.           |
| `PERETYN_DOMAIN`          | No       | The domain that the installer was given. The stack doesn't read it.         |
| `POSTGRES_PASSWORD`       | Yes      | The password of the PostgreSQL user.                                        |
| `PERETYN_INTERNAL_SECRET` | Yes      | The secret that the control plane uses to call the runtime.                 |
| `BETTER_AUTH_SECRET`      | Yes      | The secret that signs sessions.                                             |
| `PERETYN_RESEND_API_KEY`  | No       | A [Resend](https://resend.com) API key. Without it, Peretyn sends no email. |
| `PERETYN_EMAIL_FROM`      | No       | The sender of auth email. Defaults to `no-reply@peretyn.dev`.               |
| `PERETYN_ALLOW_SIGNUP`    | No       | `true` lets anyone sign up. Defaults to `false`.                            |
| `PERETYN_REQUEST_TIMEOUT` | No       | How long the runtime spends on one request. Defaults to `5s`.               |

## Connect the SDK and the CLI

Caddy serves the runtime and the dashboard on the same domain. Use your domain wherever the docs use `app.peretyn.dev`:

```sh
export PERETYN_RUNTIME_URL=https://peretyn.example.com
export PERETYN_CONTROL_URL=https://peretyn.example.com
```

## Where data lives

Compose names everything after the `peretyn` project:

| Location                | Holds                                                                                                                |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `peretyn_postgres-data` | The PostgreSQL database `peretyn`: accounts, organizations, projects, API keys, models, tuples and their change log. |
| `peretyn_caddy-data`    | Caddy's TLS certificates and their keys.                                                                             |
| `peretyn_caddy-config`  | Caddy's saved configuration.                                                                                         |
| `/opt/peretyn`          | `compose.yaml`, the `Caddyfile`, and `.env` with every secret.                                                       |

The database has two schemas. The control plane owns `peretyn_control`: accounts, sessions, organizations, projects, environments and schema versions. The runtime owns `peretyn_runtime`: the hashes of API keys, and the OpenFGA tables that hold models, tuples and the change log.

The containers keep no other state. Caddy gets a new certificate if `peretyn_caddy-data` is lost.

## Back up and restore

### Back up

Run `pg_dump` from the install directory. The `-T` flag keeps Docker from attaching a terminal, which would corrupt the dump:

```sh
cd /opt/peretyn
docker compose exec -T postgres pg_dump -U peretyn -Fc peretyn > peretyn.dump
```

The dump is consistent while the stack runs. Copy it off the host, together with `.env`. The dump holds no secrets, but you need `.env` to run the restored stack with the same secrets.

### Restore

Restore into the same `PERETYN_TAG` that made the backup, then [upgrade](#upgrade). The runtime and the control plane hold connections to the database, so stop them first:

```sh
cd /opt/peretyn
docker compose stop runtime control dashboard
docker compose exec -T postgres dropdb -U peretyn peretyn
docker compose exec -T postgres createdb -U peretyn peretyn
docker compose exec -T postgres pg_restore -U peretyn -d peretyn < peretyn.dump
docker compose up -d
```

`dropdb` deletes the current data, so make sure that the dump is the one you want.

To restore on a new host, put `compose.yaml`, the `Caddyfile` and your old `.env` in the install directory, as in [Install by hand](#install-by-hand). Run `docker compose up -d postgres`, then the commands above.

## Upgrade

Run the installer again. It keeps `.env` and its secrets, moves `PERETYN_TAG` and the deploy files to the latest release, then pulls the new images and restarts. Set `PERETYN_TAG` to pick a version.

By hand: change `PERETYN_TAG` in `.env`, then pull the new images and restart:

```sh
docker compose pull && docker compose up -d
```

The runtime and the control plane update their database tables when they start. If an update would delete data, the control plane doesn't start, and its log says `aborted: destructive statements`. [Back up](#back-up) before you upgrade.

Downgrades aren't tested. To go back to an older version, restore the backup that you made before the upgrade, with the older `PERETYN_TAG`.

## Uninstall

To stop Peretyn and keep the data, run this from the install directory:

```sh
docker compose down
```

The volumes stay. `docker compose up -d` starts the stack again with the same data.

To delete everything, including every tuple, account and certificate:

```sh
cd /opt/peretyn
docker compose down --volumes --rmi all
cd / && rm -rf /opt/peretyn
```

This can't be undone. [Back up](#back-up) first if you might need the data.
