---
title: Self-hosting
description: Run the Peretyn stack on your own server with Docker Compose.
---

The Compose stack runs Peretyn on one host: the runtime, the control plane, the dashboard, PostgreSQL, and Caddy in front of them. Caddy gets a TLS certificate for your domain, and it is the only service that publishes ports.

You need a Linux host with Docker, a domain whose DNS record points at the host, and ports 80 and 443 open.

## Install

Run the installer as root:

```sh
curl -fsSL https://raw.githubusercontent.com/peretyn/peretyn/main/deploy/install.sh | sh
```

It asks for your domain and the first admin's email, then:

- pins the latest `@peretyn/runtime` release and downloads `compose.yaml` and the `Caddyfile` from that release into `/opt/peretyn`,
- generates every secret into `.env`, readable only by its owner,
- starts the stack,
- creates the admin account and prints its password once.

To install somewhere else, or as a user in the `docker` group, set `PERETYN_DIR` to a directory you own.

### Unattended install

Every question has a variable. Set them and the installer asks nothing:

```sh
curl -fsSL https://raw.githubusercontent.com/peretyn/peretyn/main/deploy/install.sh |
  PERETYN_DOMAIN=peretyn.example.com PERETYN_ADMIN_EMAIL=you@example.com PERETYN_ADMIN_NAME='Your Name' PERETYN_RESEND_API_KEY= sh
```

| Variable                 | Description                                                            |
| ------------------------ | ---------------------------------------------------------------------- |
| `PERETYN_DOMAIN`         | The domain that Caddy serves. Required.                                |
| `PERETYN_ADMIN_EMAIL`    | The first admin's email. Required.                                     |
| `PERETYN_ADMIN_NAME`     | The first admin's name. Set it empty to use the email's local part.    |
| `PERETYN_RESEND_API_KEY` | A [Resend](https://resend.com) API key. Set it empty to send no email. |
| `PERETYN_TAG`            | The version to install. Defaults to the latest release.                |
| `PERETYN_DIR`            | The install directory. Defaults to `/opt/peretyn`.                     |

### Verify before running

Each `@peretyn/runtime` release carries `install.sh` and its `SHA256SUMS`. Download both from the release, check the script, read it, then run it:

```sh
gh release download '@peretyn/runtime@<version>' -R peretyn/peretyn -p install.sh -p SHA256SUMS
sha256sum -c SHA256SUMS
sh install.sh
```

### Install by hand

#### 1. Download the files

```sh
mkdir -p /opt/peretyn && cd /opt/peretyn
base=https://raw.githubusercontent.com/peretyn/peretyn/main/deploy
curl -fsSLO "$base/compose.yaml"
curl -fsSLO "$base/Caddyfile"
curl -fsSL "$base/.env.example" -o .env
```

#### 2. Fill in `.env`

Set every variable that [Configuration](#configuration) marks as required. Generate each secret with `openssl rand -hex 32`.

#### 3. Start the stack

```sh
docker compose up -d
```

#### 4. Enroll the first admin

Sign-up is closed by default, so create the first account from the command line:

```sh
docker compose exec control node services/control/dist/scripts/enroll.js you@example.com 'password' 'Your Name' --admin
```

## Enroll more people

Create other accounts the same way, without `--admin`, from the install directory:

```sh
docker compose exec control node services/control/dist/scripts/enroll.js teammate@example.com 'password' 'Their Name'
```

Admins manage users through the better-auth admin endpoints under `/api/auth/admin/*`.

## Configuration

| Variable                  | Required | Description                                                                 |
| ------------------------- | -------- | --------------------------------------------------------------------------- |
| `PERETYN_TAG`             | Yes      | The server version to run, such as the latest `@peretyn/runtime` release.   |
| `PERETYN_DOMAIN`          | Yes      | The domain that Caddy serves, such as `peretyn.example.com`.                |
| `PERETYN_DASHBOARD_URL`   | Yes      | The public URL of the dashboard, such as `https://peretyn.example.com`.     |
| `POSTGRES_PASSWORD`       | Yes      | The password of the PostgreSQL user.                                        |
| `PERETYN_INTERNAL_SECRET` | Yes      | The secret that the control plane uses to call the runtime.                 |
| `BETTER_AUTH_SECRET`      | Yes      | The secret that signs sessions.                                             |
| `PERETYN_RESEND_API_KEY`  | No       | A [Resend](https://resend.com) API key. Without it, Peretyn sends no email. |
| `PERETYN_EMAIL_FROM`      | No       | The sender of auth email. Defaults to `no-reply@peretyn.dev`.               |
| `PERETYN_ALLOW_SIGNUP`    | No       | `true` lets anyone sign up. Defaults to `false`.                            |
| `PERETYN_REQUEST_TIMEOUT` | No       | How long the runtime spends on one request. Defaults to `5s`.               |

## Connect the SDK and the CLI

Caddy serves the runtime and the dashboard on the same domain. Use your domain wherever the docs use `app.peretyn.dev`:

```sh
export PERETYN_RUNTIME_URL=https://peretyn.example.com
export PERETYN_CONTROL_URL=https://peretyn.example.com
```

## Upgrade

Run the installer again. It keeps `.env` and its secrets, moves `PERETYN_TAG` and the deploy files to the latest release, then pulls the new images and restarts. Set `PERETYN_TAG` to pick a version.

By hand: change `PERETYN_TAG` in `.env`, then pull the new images and restart:

```sh
docker compose pull && docker compose up -d
```

## Back up

All data is in the `postgres-data` volume. Back it up with `pg_dump`:

```sh
docker compose exec postgres pg_dump -U peretyn peretyn > peretyn.sql
```
