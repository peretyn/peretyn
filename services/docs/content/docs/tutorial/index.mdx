You've spent months building it, and next week it finally goes live: a shared drive for companies. People will upload documents, share them with colleagues, sort them into folders and send out public links. It all works on your machine. What you haven't quite figured out yet is the question hiding underneath every one of those features: is this person allowed to do this?

That question is about to follow you through the weeks ahead. Each chapter of this tutorial is a stretch of that story. Your users come to you with a request, you try the obvious solution first, and you watch it start to crack. Then you reach for Peretyn and grow your <Term name="schema">schema</Term> just enough to handle the request properly. By the last chapter, you'll have used every building block a schema has to offer, and you'll know exactly when to reach for each one.

## Before you start

Before launch day, you need a few things in place. Finish the [Quickstart](/quickstart) first, so you have its environment variables, the CLI and the SDK.

Then set up a fresh directory for the drive, just like you did in the quickstart:

```sh
mkdir shared-drive
cd shared-drive
npm init -y
npm pkg set type=module
```

```npm
npm install @peretyn/sdk
```

Stick with the same `development` key for the whole tutorial. Each chapter picks up the tuples that the earlier chapters left behind, so the story only makes sense if you follow it in order.

## How each chapter works

Each chapter tells its story one step at a time. In every step, a new request lands on your desk, and you change the schema only as much as that request needs, never more. Each step comes with a small script that saves the new <Term name="tuple">tuples</Term> and runs the new <Term name="check">checks</Term>, so you can watch the answers change as the story moves along. The file name of each script is in the title of its code block. If words like tuple and check are new to you, [Concepts](/concepts) explains them in a few minutes.

When the chapter is over, its last section, **Run it**, hands you the keyboard:

1. The full `schema.ts` and `helpers.ts` as they stand at the end of the chapter. Replace your files with them.
2. The commands that publish the schema. Each chapter uses the next label: `tutorial-v1` in the first chapter, `tutorial-v2` in the second, and so on. The Quickstart already used `v1` in this environment, and a label can only be used once, so the tutorial has labels of its own.
3. The step scripts, which you run in order with `node`. Each one prints the output shown in its step.

Your schema only ever grows. Later chapters add types and relations, but they never remove or rename one, so the tuples you saved along the way keep working.
